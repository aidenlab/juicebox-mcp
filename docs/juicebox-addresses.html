A Room’s addresses

A Room is a live relay channel on the server that Pages join. Its id is ten letters and digits. A Host reaches it through its MCP session: the server mints the session id on initialize, in the mcp-session-id header, and a session drives the Room of the same name unless join_room has bound it to another. No other tool takes a room argument. Press New Room to open one on the chosen Deployment, the way a Host does, or paste an id from a Join link or from geenee.

AddressWhat it showsWho uses it
The Join link. The Page joins the Room, and its Room indicator in the Header turns green: “Joined room …”. The model, which opens it beside the conversation, and anyone it is shared with.
Not a page: the WebSocket the Page opens to its Room. Refused with 403 from an origin not in ALLOWED_ORIGINS, 400 for a malformed id. With no room, the server mints one. The Page, for as long as it is open.

A Room expires 24 hours after the last message from a Page, and what it held is deleted. A Page still connected keeps the Room going, empty. With no Page left it stays gone: a Page that joins is refused, turns its indicator red, “Room expired. Ask Claude to open Juicebox again.”, and stops trying to reconnect.

From the terminal

Each command uses the Deployment and Room chosen above. /mcp needs no sign-in. The Room travels in the mcp-session-id header, so every call but tools/list sends it.

Prints the Join link, with the new Room id in it. This is what New Room does: initialize for the id, then get_juicebox_url in that Room.



Drive the Page




With the Join link open, the Page loads a GM12878 Hi-C map from 4DN, 4DNFI1UEG1HD. Any tool from the list below works the same way, sent with the Room’s mcp-session-id.

Tricks worth knowing


    
  
  • Any session id is a Room. The server takes whatever mcp-session-id it is sent, even one it never minted, and drives the Room of that name. A mistyped id is not refused: it quietly drives an empty Room, and one that is not ten Crockford characters drives a Room no Page can ever join.
    • 
  
  • Join a Room a Page started. join_room binds this session to another Room, such as one from a Join link pasted into the conversation. After it, every tool drives that Room, and get_juicebox_url answers its Join link.
    • 
  
  • Two prods. One build runs as geenee’s Juicebox, prod here, and as the public Juicebot, juicebot, whose Page is juicebot.3dg.io. docs/why-two-prod-deployments.md says why.
    • 
  
  • geenee’s Room id works here. geenee sends its own Room id as the session, so an id from a geenee Card drives the same Page that geenee’s Workspace frames.
    • 
  
  • A Snapshot link can seed a Room. Add &session=… to a Join link and the Page starts from that snapshot, unless the Room already holds a view of its own, which wins.
    • 
  
  • The Page’s own Join link keeps only ?room=, and drops ?session= and the hash. geenee adds &embedded when it frames the Page; the Page ignores it.
    • 
  
  • Local development runs the Page on localhost:5173 (npm run dev) in juicebox-view, and this Worker on localhost:8787 (npm run dev:server). The Page reaches the Worker’s /ws through its own origin.
