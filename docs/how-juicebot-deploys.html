How Juicebot deploys

Juicebot is deployed to Cloudflare as a Page and a Worker. This document describes each one, how they are connected, and how they are deployed.

Pages, Workers, Durable Objects

Juicebot uses three Cloudflare features.

A Pages project holds files. You build the site on your machine into dist/ (HTML, JavaScript, CSS) and upload that folder. Pages serves the files at the project’s address. The code in them runs in the browser.

A Worker holds code. You upload a JavaScript program. Cloudflare runs it on each request to the Worker’s address. There is no server to manage. The Worker keeps nothing between requests.

A Durable Object keeps state for a Worker. The Worker creates or finds an object by giving Cloudflare an id string. Only one object exists per id, and each has its own storage. Juicebot uses room ids (such as 7KQ2M9XA4T) and MCP session ids. All pages in Room 7KQ2M9XA4T connect to the same object.

One stack

A stack is one Page and one Worker configured to work together. Figure 2 shows production. The development stacks are the same except for their names.

Tool calls come from Anthropic’s servers, so the Worker needs a public https:// address, including for testing.
  1. The person opens a join link. The browser loads the page’s files from Pages (A).
  2. The page opens a WebSocket to the Worker (B). The Worker passes it to the Room’s Durable Object.
  3. Claude calls a tool on the Worker (C).
  4. The Worker sends a command over the WebSocket. The page runs it and replies.

After the files load, Pages is not involved.

How the Page and Worker connect

Three settings connect a Page to its Worker.

SettingLives inSaysIf it is wrong
1VITE_WS_URLThe page’s JavaScript, fixed when it is builtWhich Worker this page connects to.The page does not connect, or connects to another stack’s Worker.
2ALLOWED_ORIGINSwrangler.toml, the stack’s varsWhich page addresses may open a WebSocket. It must match exactly, scheme and all.The Worker refuses the page (403).
3BROWSER_URLwrangler.toml, the stack’s varsWhich page the join links and snapshot links open. The trailing slash matters.Claude’s links open the wrong page.

VITE_WS_URL is written into the page’s JavaScript at build time. To change it, rebuild and redeploy the page.

What a deploy does

A deploy builds the Worker and the Page on your machine from a git tag or branch, and uploads them. Uncommitted changes are not deployed.

Worker. wrangler deploy --env prod bundles src/index.js with the prod settings from wrangler.toml and uploads it. The new version is live within seconds. Room storage is kept; open WebSockets drop and the pages reconnect.

Pages can also build from GitHub. Juicebot builds locally so the script can set VITE_WS_URL.

Page. vite build writes dist/ with VITE_WS_URL. The script checks the address is in the built files, then wrangler pages deploy uploads dist/. The project’s address serves the new upload immediately. Earlier uploads remain at <hash>.juicebot-web.pages.dev.

The stacks

Each [env.name] section of wrangler.toml deploys the same Worker code with its own name, address, settings, secrets and Durable Objects. Stacks share no data.

The dev stack is shared: a deploy replaces the previous one. To undo, redeploy the earlier branch or tag.

Development names end in -dev. The production Pages project is still called juicebot-web, from before the page moved to juicebox-view; its address did not change. The top level of wrangler.toml (outside any [env]) is only shared settings and the values for wrangler dev; it names no address.

3dg.io is a zone on the same Cloudflare account, so Workers and Pages projects can use addresses in it. Every Pages project also has a <project>.pages.dev address; the dev stack uses only that.

Releasing and rolling back

Production is deployed only from a tag. The same tag, such as prod-2026-10-11, goes on juicebox-mcp main and juicebox-view main. A second release that day is prod-2026-10-11.1.

  1. Tag both repos with the same prod- name, and push both tags.
  2. Run scripts/deploy-prod.sh prod-2026-10-11. It refuses a tag that is missing from either repo’s origin.
  3. To roll back, run it with the previous tag. Tags up to prod-2026-10-11.1 built juicebox-web; roll back to one of those by running the script from a worktree at that tag, with WEB_REPO set to a clone of weiszd/juicebox-web (the only repo that holds those tags).

One tag for both repos keeps the Page and Worker versions matched.

Settings and secrets

Settings live in three places.

PlaceHoldsWho can read itA change takes effect
wrangler.toml varsBROWSER_URL, ALLOWED_ORIGINS, TINYURL_DOMAINAnyone: the file is in gitOn the next wrangler deploy of that stack
Worker secretsTINYURL_API_KEY, SESSION_HMAC_SECRETOnly the WorkerAt once: wrangler secret put NAME --env stack deploys a new version
The page buildVITE_WS_URLAnyone: it is in the page’s JavaScriptOn the next build and upload of the page

Secrets are per stack. For wrangler dev, secrets come from packages/server/.dev.vars, which is not in git.

Variables set in the Pages dashboard are ignored by direct uploads.

Stored state: Pages keeps the uploaded files. Each Room keeps the last saved session, deleted 24 hours after the last message. Each Session keeps the Room it is bound to. The Worker keeps nothing.

Glossary

Account
Owns all the resources here. Its id is in wrangler.toml.
Zone
A domain whose DNS Cloudflare runs: 3dg.io.
Pages project
A static site. Each upload is a deployment; the newest is served at the project’s address.
Worker
A program Cloudflare runs on each request to its address.
Environment
A section [env.name] of wrangler.toml that deploys the same code as a separate Worker. Chosen with --env.
Durable Object
An object with storage, owned by a Worker and found by an id string; one per id. Juicebot’s are WebSocketRoom and McpSession.
Binding
How Worker code reaches another Cloudflare resource. WEBSOCKET_ROOM and MCP_SESSION bind the two Durable Objects.
Custom domain
An address in a zone, such as juicebot-mcp.3dg.io, used instead of or beside the default workers.dev or pages.dev address.
wrangler
Cloudflare’s command-line tool. Run npx wrangler login once; the scripts use it after that.
